PIISC SCHOOL BACKEND — ENGINEERING HANDOFF
Read-only source inspection. No secrets or .env values are included.

1. STACK

- Runtime: Node.js, CommonJS. The project does not declare an engines field or
  provide a .nvmrc/.node-version file. Installed Mongoose 9.11.1 requires
  Node >=20.19.0; use a compatible Node release.
- Framework: Express 5.3.0.
- Database/ODM: MongoDB through Mongoose 9.11.1.
- Authentication: JWT signed with HS256. Login returns the token in JSON;
  protected routes expect Authorization: Bearer <token>. No cookie auth,
  refresh-token route, or logout route was found. JWT lifetime comes from
  JWT_EXPIRES_IN and defaults to 1d.
- Validation: no separate Joi/Zod/validation library found. Controllers perform
  manual input checks and Mongoose schemas validate/cast model data.
- Main dependencies: bcryptjs, cors, dotenv, express, express-rate-limit,
  helmet, jsonwebtoken, mongoose. Development dependency: nodemon.

4. ROUTES

all of them. Rate-limit responses are 429:
  {"message":"Too many attempts. Please try again later.","code":"RATE_LIMITED"}

Global errors for routes not caught in a controller:
- 400 malformed JSON: {"message":"Invalid JSON"}
- 413 oversized JSON: {"message":"Request too large"}
- 400 Mongoose validation: {"message":"Validation failed","errors":[...]}
- 400 cast error: {"message":"Invalid value"}
- 409 duplicate key: {"message":"Duplicate value"}
- 500: {"message":"Something went wrong"}
- Unknown path: 404 {"message":"Route not found"}

5. NOTICES FEATURE

Schema fields (src/models/Notice.js):
- title: required string, trimmed, 3–150 chars.
- content: required string, minimum 10 chars; no maximum declared.
- category: enum general, admission, event, holiday, exam, meeting; default general.
- isImportant: boolean, default false.
- isPublished: boolean, default true.
- publishDate: date, default current time.
- expiryDate: optional date; when present it must be after publishDate.
- createdBy: optional ObjectId reference to User, select:false. Older notices
  may not have it; admin create sets it from the authenticated user.
- timestamps are enabled. Public list/detail omit __v and createdBy.

Routes and publication behavior:
- GET /api/notices is public and returns only isPublished=true notices whose
  publishDate is not in the future and whose expiryDate is absent/null or future.
- GET /api/notices/:id is public and applies the same visibility filter.
- GET /api/notices/manage is admin-only and includes published, draft, scheduled,
  and expired records. Optional filters are category and isPublished. Sort is
  createdAt descending. It populates createdBy with name (and MongoDB's default
  _id unless explicitly excluded).
- POST, PATCH, DELETE are admin-only. Create/update whitelist title, content,
  category, isImportant, isPublished, publishDate, expiryDate. createdBy is not
  accepted from request bodies; update does not alter it.
- No separate publish/unpublish route was found; admins publish/unpublish by
  setting isPublished in create or patch.

Representative request/response JSON:

GET /api/notices?page=1&limit=20&category=event
Response:
{"notices":[],"pagination":{"page":1,"limit":20,"total":0,"totalPages":0}}

GET /api/notices/manage?isPublished=false&page=1&limit=20
Response:
{"notices":[{"_id":"<id>","title":"Draft title","content":"Draft content text",
"isPublished":false,"createdBy":{"_id":"<user id>","name":"Admin name"}}],
"pagination":{"page":1,"limit":20,"total":1,"totalPages":1}}

POST /api/notices (admin)
Request:
{"title":"Annual Sports Day","content":"Sports day will be held at school.",
"category":"event","isImportant":true,"isPublished":false,
"publishDate":"2027-02-01T00:00:00.000Z"}
Response: 201 with the created notice document. createdBy is assigned from the
authenticated user, not from this request.

PATCH /api/notices/<id> (admin)
Request: {"isPublished":true}
Response: 200 with the updated notice document.

DELETE /api/notices/<id> (admin)
Response: {"message":"Notice deleted successfully","id":"<notice id>"}

6. AUTH, CORS, COOKIES, PROXY, RATE LIMITS

- Login issues a signed HS256 JWT in the JSON response. Clients send it in the
  Authorization: Bearer header. No cookie configuration, logout endpoint, or
  refresh route was found. JWT_EXPIRES_IN defaults to 1d.
- Expired token response is 401
  {"message":"Not authenticated","code":"TOKEN_EXPIRED"}. Other invalid or
  absent tokens return 401 {"message":"Not authenticated"}.
- JWT role claims are not trusted for authorization; middleware reloads the user
  from MongoDB on each protected request. User password hashes are select:false
  and also removed by JSON/object transforms.
- CORS uses CLIENT_URL as a comma-separated exact-origin list, trimming spaces
  and trailing slashes. Requests without Origin are allowed; a disallowed origin
  gets no CORS permission headers. Allowed methods: GET, POST, PATCH, DELETE,
  OPTIONS. Allowed headers: Content-Type, Authorization. maxAge 600; credentials
  disabled. No wildcard origin is configured.
- Helmet uses default settings. JSON request size limit is 50kb.
- TRUST_PROXY is optional and unset by default; numeric strings become numbers.
  Code comments recommend 1 behind Render. Configure only for the actual trusted
  proxy topology.
- Rate limits (express-rate-limit, in-memory default store): all /api 300/IP per
  15 minutes; login 20/IP and 5/IP+normalized identifier per 15 minutes;
  change-password 5/IP per 15 minutes. The three auth-specific limits skip
  successful requests. Standard RateLimit headers on; legacy headers off.

7. PRODUCTION READINESS GAPS / NOTES

- npm run seed executes Notice.deleteMany() before inserting sample notices.
  This is destructive to the notices collection; do not use against production.
- /api/auth/_test-protected and /api/auth/_test-admin remain in the routes file
  and are marked temporary. They are protected, but should be reviewed for
  removal before release.
- Rate-limit state is in memory, resets on restart, and is separate per instance.
- No JWT revocation/refresh/logout mechanism was found. Password reset sets
  mustChangePassword, blocking strict protected routes, but older JWTs can become
  usable again after the user changes the password.
- /api/health returns a static status and does not report ongoing database health.
- Temporary passwords are returned once to admin callers on user create/reset;
  responses set Cache-Control: no-store.
- Helmet, CORS, body-size limits, rate limits, not-found handling, and a safe
  JSON error handler are present. In development, error stacks are written to
  server logs; in production, error name/message are logged. They are not sent
  in normal error JSON responses.
